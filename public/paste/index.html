What is RedSecPaste?

RedSecPaste is a privacy-first encrypted pastebin built by RedSec Offensive Security. It lets you share text, code snippets, and sensitive notes through end-to-end encrypted links that even the server cannot read. No accounts, no tracking, no plaintext ever touches our infrastructure.

How Encryption Works

Link-Only Encryption (default)

When you create a note without a password, your browser generates a random 256-bit AES key and encrypts your note locally using AES-256-GCM. The key is never sent to the server.

The resulting share link contains the key in the URL fragment (after the #). URL fragments are never transmitted to the server by browsers, so the server only ever stores unreadable ciphertext.

https://example.com/p/paste_id#encryption_key

The server only sees the paste ID. The key after # stays in the browser.

Password-Protected Notes (double encryption)

Adding a password applies a second layer of encryption on top of the link-based encryption:

  1. Your note is encrypted with a random key K (stored in the URL fragment)
  2. The resulting ciphertext is then re-encrypted with a key derived from your password using PBKDF2 with 600,000 iterations and SHA-256
  3. Only the doubly-encrypted ciphertext is sent to the server

To decrypt, the recipient needs both the link (containing key K) and the password. Neither alone is sufficient.

Security Features

  • Zero-knowledge server — the server never has access to your plaintext or encryption keys.
  • Burn after reading — notes can be set to self-destruct immediately after the first viewing.
  • Auto-expiry — all notes automatically expire and are permanently deleted.
  • Strict CSP & security headers — HSTS, Content Security Policy, no-referrer, and frame blocking enforced.
  • No tracking — no cookies, no analytics, no accounts.
  • Syntax highlighting — 30+ languages, applied client-side after decryption.
