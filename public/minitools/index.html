About RedSecMiniTools

RedSecMiniTools is a collection of focused security utilities for quick analysis, lookup, decoding, and evidence-gathering tasks. Some tools run fully in the browser; others use server-side API calls so keys, network controls, rate limits, and audit behaviour stay under the application.

CyberChef

CyberChef is the local transform workbench for decoding, encoding, extracting, hashing, and cleaning evidence without sending the input to a server.

Use It For

  • Chaining repeatable transforms against payloads, logs, tokens, headers, and copied evidence.
  • Fast Base64, Base64 URL, Base32, hex, URL, HTML entity, ROT13, Caesar, XOR, AES, RC4, JSON, JWT, and URL parsing tasks.
  • Extracting IPs, IPv6 addresses, URLs, emails, domains, hashes, and simple indicators from raw text.

Workflow

  • Paste text into the input panel, add operations to the recipe, then bake the output.
  • Use recipe search and categories to find operations quickly; swap input/output when iterating.
  • Use hashing, HMAC, entropy, line sorting, unique lines, regex match, find/replace, and whitespace cleanup for evidence prep.

Privacy And Limits

  • Transforms run in the browser. Data is not uploaded unless you copy it into another server-backed MiniTool.
  • The tool is for manipulation and inspection only; it does not execute decoded payloads.

JWT Analyzer

JWT Analyzer decodes, edits, rebuilds, and verifies JSON Web Tokens locally for token review and authentication testing notes.

Inputs

  • Paste a JWT to split the header, payload, and signature.
  • Decode standard claims such as iss, sub, aud, exp, nbf, iat, jti, scope, scp, and roles.
  • Azure-style claims such as tenant ID, object ID, app ID, identity provider, and username fields are labelled when present.

Verification

  • Verify HMAC tokens with a shared secret.
  • Verify RSA, RSASSA-PSS, and ECDSA signatures with PEM or JWK public keys.
  • Flag obvious risks such as alg: none, missing expiry or audience, and unusually long token lifetime.

Important Limits

  • Decoded claims are not proof of trust. A token is only meaningful when the correct issuer, audience, algorithm, and key are validated by the target system.
  • Rebuilding a token is for testing and documentation; it does not bypass a correctly verified signature.

Header Analyzer

Header Analyzer is for raw email headers. It reconstructs delivery flow and authentication signals from copied message headers.

Use It For

  • Paste full email headers from a suspicious message, ticket, or mail client export.
  • Review Received hops, sender metadata, authentication results, DKIM signatures, and message identifiers.
  • Build a cleaner summary for phishing triage, client evidence, or escalation notes.

Outputs

  • Delivery path timeline with source and relay information where the headers expose it.
  • SPF, DKIM, and DMARC result parsing from Authentication-Results style headers.
  • DKIM selector, domain, algorithm, canonicalisation, signed header, and expiry tags when present.

Limits

  • The tool parses supplied headers; it does not prove that an upstream mail server is truthful.
  • It does not fetch DKIM public keys or query DNS. Use DNS Intelligence for selector checks.

CVSS Calculator

CVSS Calculator builds CVSS 3.1 and CVSS 4.0 vectors with consistent scoring for findings, tickets, and report evidence.

Workflow

  • Select CVSS version, set each metric, and review the calculated score and severity.
  • Copy the vector string into Reporter, issue trackers, or client evidence.
  • Use environmental and business context outside the calculator when finalising risk.

Use It For

  • Consistent scoring across repeat findings and multiple reviewers.
  • Quick comparison between CVSS 3.1 and 4.0 language when a client requires a specific version.

LOL Lookup

LOL Lookup is a local reference index for LOLBAS, GTFOBins, and LOLDrivers. It preserves practical commands and metadata from the upstream datasets without doing live lookups on each search.

Search Modes

  • Quick search: names, descriptions, commands, functions, paths, tags, ATT&CK IDs, vendors, signers, and hashes.
  • Exact lookup: pasted binary names, driver names, or exact identifiers.
  • Command lookup: paste a command and identify relevant LOLBAS or GTFOBins entries.
  • Hash lookup: searches LOLDrivers first for SHA256, SHA1, and MD5 matches.

Results

  • LOLBAS entries show functions, paths, command examples, notes, detections, ATT&CK mappings, and references.
  • GTFOBins entries show function-specific payloads such as shell, sudo, SUID, file read, file write, upload, download, and command execution.
  • LOLDrivers entries show filenames, hashes, signer/vendor details, tags, known behaviour, references, and detection or blocklist context when available.

Cache And Freshness

  • Runtime search uses the local database projection only, so upstream outages do not break lookup.
  • Dataset status shows entry count, last successful sync, last attempt, backup count, stale state, and errors.
  • Admin refresh validates new source data before replacing the previous known-good dataset.

Security Headers

Security Headers analyses HTTP response headers for browser-side security controls and practical remediation guidance.

Inputs

  • Enter a public host or URL. If no scheme is provided, HTTPS is assumed.
  • Paste raw response headers when you already collected them with curl, Burp, a proxy, or browser dev tools.
  • Use the sample action to see the expected raw-header format.

Checks

  • Grades CSP, HSTS, X-Frame-Options, X-Content-Type-Options, Referrer-Policy, Permissions-Policy, cache controls, disclosure headers, cookies, and related protections.
  • Labels findings as pass, warn, fail, or info with copy-ready evidence and suggested fixes.

Network Safety

  • URL fetches run server-side through public-target validation, redirect checks, timeout limits, and response-size controls.
  • Use pasted-header mode when analysing private systems or captured traffic that the server should not fetch.

TLS Check

TLS Check inspects public TLS endpoints for certificate, DNS, chain, CT, and optional cipher evidence.

Inputs And Options

  • Enter example.com or example.com:8443; HTTPS scheme is not required.
  • Enable DNS checks for A/AAAA, NS, MX, CAA, SPF, DMARC, DNSSEC, wildcard DNS, AXFR attempt, and per-IP certificate consistency.
  • Enable Certificate Transparency for crt.sh names and enable cipher scan only when slower protocol and cipher probing is needed.

Outputs

  • Certificate subject, issuer, SANs, validity, fingerprints, key type/size, signature algorithm, key usage, EKU, TLS version, cipher, ALPN, and chain notes.
  • Findings for expiry, hostname mismatch, weak protocols, weak ciphers, private/internal SAN leakage, self-signed certificates, and DNS posture issues.
  • Export JSON, CSV, or Markdown evidence for reports.

DNS Intelligence

DNS Intelligence runs controlled public DNS and lightweight domain posture checks through selectable public resolvers.

Primary Checks

  • Security DNS Report is selected by default for SPF, DMARC, CAA, DNSSEC, DKIM selector, wildcard DNS, authoritative server, and hygiene checks.
  • DNS Records supports A, AAAA, MX, TXT, NS, SOA, CAA, SRV, CNAME, PTR, DS, DNSKEY, and RRSIG where available.
  • Other modes include DNSSEC test, reverse DNS, mail DNS health, resolver consistency, HTTP headers, site availability, DNSBL check, and URL decode.

Resolvers And Safety

  • Basic lookups use selectable public resolvers, with Cloudflare as the default and Google, Quad9, and OpenDNS available.
  • The tool avoids using the server's internal resolver for normal domain lookups to reduce internal network mapping risk.
  • Targets are validated and local/private network probing is blocked where the tool could touch network services.

Port And Web Checks

  • Light port check is intentionally limited to common ports only: FTP 21, SSH 22, DNS 53, HTTP 80, HTTPS 443, SMTP 25/587, IMAPS 993, and POP3S 995.
  • Port status is reported as open, closed, or filtered; it does not do ranges, custom ports, exploit checks, or banner grabbing.
  • HTTP header and availability checks use safe public-target fetch controls.

API Analyzer

API Analyzer reviews pasted or uploaded API definitions for security testing leads, auth coverage, and exportable test artefacts.

Inputs

  • Paste or upload OpenAPI, Swagger, or Postman JSON/YAML definitions.
  • Uploaded definitions are limited to 5 MB.
  • The analyzer parses the supplied definition only; it does not crawl or call the target API.

Finds

  • Auth schemes, unauthenticated endpoints, destructive methods, file upload/download, bulk actions, callbacks/webhooks, sensitive operations, and sequential or weak object references.
  • BOLA/IDOR-style candidates, object identifiers, parameter risk, and useful endpoint grouping for testing.
  • Filters help focus by method, auth state, tag, and risk area.

Exports

  • Export CSV, cURL commands, Burp-friendly requests, Markdown sections, and unauthenticated endpoint lists.
  • Findings are starting points; validate behaviour against the live API and its real authorisation controls.

Secrets Detector

Secrets Detector scans pasted text or local text files in the browser for likely credentials, tokens, keys, and suspicious auth usage.

Inputs

  • Paste raw text or upload supported text-based files up to 10 MB.
  • Use it for config files, logs, source snippets, environment dumps, proxy exports, and ticket attachments.

Detection Coverage

  • Looks for AWS, GitHub, GitLab, Slack, Discord, Google, Stripe, SendGrid, Mailgun, Twilio, OpenAI, Anthropic, NVIDIA, Gemini, JWT, bearer/basic auth, URL credentials, database strings, private keys, PGP blocks, Kubernetes, Docker, npm, and context-based password/token patterns.
  • Findings are grouped by severity with snippets, context lines, filters, and detail expansion.

Privacy And Handling

  • Scanning runs in the browser. Full secret values can be displayed, copied, or exported, so treat the screen and exports as sensitive.
  • Results are indicators, not proof that a credential is valid. Confirm ownership and rotate through the proper process.

Azure Mapping

Azure Mapping queries public Microsoft discovery endpoints to identify Entra ID tenant information associated with a domain.

Use It For

  • Map tenant ID, OpenID configuration, token and authorisation endpoints, issuer metadata, and verified domains when exposed.
  • Support phishing-resistance checks, tenant scoping, identity recon, and report evidence.

Limits

  • The tool uses public unauthenticated discovery endpoints and does not log into the tenant.
  • Absence of metadata does not prove a domain has no Microsoft identity footprint.

SecurityTrails

SecurityTrails queries the configured SecurityTrails account for domain and reverse-IP intelligence from inside RedSecMiniTools.

Modes

  • Details: domain metadata and DNS intelligence available from SecurityTrails.
  • Subdomains: known subdomain records for a domain.
  • Both: details and subdomains in one request flow.
  • Reverse IP: domains associated with a supplied IP address where the upstream API returns them.

Controls

  • The API key is configured by an administrator and kept server-side.
  • Requests are authenticated, rate limited, and counted against the user's MiniTools daily quota and upstream account limits.

Breach Lookup

Breach Lookup checks a single email address against the configured public breach intelligence source and summarises exposure metadata.

Inputs And Results

  • Enter one email address.
  • Review breach names, exposed data classes, breach dates, verification status, password-risk indicators, and timeline information where available.
  • Use the output for exposure triage, password reset recommendations, and account-risk conversations.

Limits

  • Results depend on the upstream breach data source and may be incomplete or delayed.
  • A breach hit is evidence of exposure, not proof that the current account is compromised.

LeakRadar

LeakRadar searches the configured LeakRadar API for domain-related leak intelligence and manages unlocked records through RedSecTools.

Search Types

  • Employees, customers, third parties, and subdomains are separate upstream endpoints.
  • Results load 100 records at a time with upstream-aligned pagination and a next-page control when more records are available.
  • Previous unlocks can be listed globally or filtered by domain, ordered newest first when unlock metadata is present.

Unlock Behaviour

  • Unlock buttons call the server-side API key and update the displayed row immediately with retrieved username/account and password data.
  • Unlocked records are stored in the database so future searches can automatically show known unlocked values without another previous-unlocks call.

Controls

  • The API key is configured in Admin and kept server-side.
  • Search and unlock actions are rate limited and should only be used for authorised client or internal investigations.

Callback

Callback creates temporary inbound URLs for out-of-band testing and live request capture.

Use It For

  • SSRF verification, webhook testing, blind injection callbacks, server-side request evidence, and integration troubleshooting.
  • Create a labelled URL with an expiry from 15 minutes up to 24 hours, then use that URL in the system being tested.

Captured Data

  • Requests are delivered live through WebSocket updates and persisted for review.
  • Captured evidence can include method, path, query, headers, body, source IP metadata, and timestamps.

Handling

  • Captured headers and bodies can contain cookies, bearer tokens, API keys, or client data.
  • Revoke or delete callback URLs when testing is complete; expired and revoked URLs are cleaned up automatically after the retention window.
